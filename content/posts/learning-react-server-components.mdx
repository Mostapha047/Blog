React Server Components (RSCs) confused me at first because they look exactly like the components I already knew, but behave completely differently depending on where they run. Here's the mental model that finally made it click.

## Two kinds of components, one file tree

In the App Router, every component is a Server Component by default. They render on the server, never ship their code to the browser, and can do things client components can't — like reading files or querying a database directly:

```tsx title="app/blog/page.tsx"
import { getAllPosts } from "@/lib/posts";

// No "use client" directive: this runs on the server only.
export default function BlogPage() {
  const posts = getAllPosts();
  return (
    <ul>
      {posts.map((post) => (
        <li key={post.slug}>{post.title}</li>
      ))}
    </ul>
  );
}
```

The moment a component needs interactivity — state, effects, event handlers — it opts into being a Client Component with a directive at the top of the file:

```tsx title="components/theme-toggle.tsx" {1}
"use client";

import { useState } from "react";

export function ThemeToggle() {
  const [dark, setDark] = useState(false);
  return <button onClick={() => setDark(!dark)}>Toggle theme</button>;
}
```

## Why the split matters

The part that took longest to sink in: `"use client"` doesn't mean "this only runs in the browser." It means "this component *can* run in the browser," so React includes it (and everything it imports) in the JavaScript bundle. Server Components never do, which is what keeps bundles small — data-fetching and formatting logic just disappears from the client bundle entirely.

## A rule of thumb that helped

I ended up defaulting every new component to a Server Component and only adding `"use client"` when the compiler (or a `useState`/`useEffect` I actually needed) forced my hand. Pushing client components as far down the tree as possible — a single button, not the whole page — kept the bundle small without any real ceremony.

That's the whole model, really: server by default, client by exception, and the boundary between them is just a directive.
